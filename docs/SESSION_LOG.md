## Phase 6: Cloudflare Worker, Supabase, community data (2026-11-15)
Model: Sonnet 5.5.
- Worker (`worker/`): the only thing the app talks to. Payload guard allows only a postal code, "block street" or Singapore coordinates and rejects everything else before any upstream call. Secrets live in Cloudflare. Proxies OneMap (token renewed automatically; raw/Bearer header fallback), Overpass (query must equal the app's own; mirrors; Cache API on a coordinate grid) and openrouteservice (exact key allow-lists, 51-point cap, daily cap, 429 means "plan on the phone").
- Community: gates and pins need 2 distinct drivers within 30 m (3 to replace a community gate; owner-set gates are never replaced). Submitters are monthly-rotating salted hashes. Notes reject personal-looking text and hide after 3 distinct reports. Feedback is redacted with a whitelist of diagnostics.
- Supabase schema is deny-by-default (RLS on, no anon grants, service_role only). Run for real in PGlite in tests.
- App: `src/app/config.ts` (Worker client, kill-switch, per-device routing cap), `src/app/community.ts` (pin fix, tips, feedback, offline outbox), Run Mode "Pin or gate wrong?" panel, post-run rating, inbox feedback, `/admin` console (separate entry, no HTML injection, token in memory).
- Tests: 67 Worker tests (guards, proxy, caching, kill-switch, rate limits, consensus, admin, cron, PGlite schema) plus client tests. Mutation checks on consensus constants and the Singapore bounds caught every change.
- E2E (`tests/e2e/localWorker.ts`, real Worker code, stubbed upstreams): full flow in non-demo mode; no name, unit or phone in any browser request or Worker upstream call; PII notes blocked on device; pin report, note, rating, feedback and admin actions verified. The e2e also caught that my stub generated out-of-Singapore coordinates and the guard correctly refused them.
- Not yet exercised against the live services (needs Ali's keys): OneMap auth header scheme, real Overpass mirrors, real ORS quota behaviour.
- Next: Phase 7 (Opus 5.5): PDPA payload guard as a CI test over the whole app, E2E suite, security review, go-live gates.
